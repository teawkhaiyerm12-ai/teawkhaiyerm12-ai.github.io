# โต๊ะ QR — ระบบสั่งอาหารผ่าน QR Code

ลูกค้าสแกน QR ที่โต๊ะ → สั่งอาหารเอง → ออเดอร์เด้งขึ้นจอหลังร้านทันที

static HTML ล้วน ไม่มี build step ไม่มี `node_modules` — แก้ไฟล์แล้ว push ขึ้น GitHub เว็บอัปเดตเอง

---

## โครงไฟล์

```
qr-order/
├── firebase.json              ตั้งค่า Hosting + rewrite /t/**
├── .firebaserc                project id            ← ต้องแก้

├── firestore.indexes.json
├── .github/workflows/deploy.yml   push main แล้ว deploy อัตโนมัติ
└── public/
    ├── index.html             หน้าแรก

    ├── admin/
    │   ├── index.html         ล็อกอิน + ออเดอร์สด
    │   ├── menu.html          ตั้งค่าร้าน + จัดการเมนู
    │   ├── report.html        ยอดขายวันนี้ + รายเดือน
    │   └── tables.html        โต๊ะ + gen QR + ปริ้น
    └── assets/
        ├── config.js          Firebase config      ← ต้องแก้
        ├── core.js            init + helper ทั้งหมด (จุดเดียวที่ import SDK)
```

## โครงข้อมูลใน Firestore

| Path | ข้างใน | ใครอ่านได้ |
|---|---|---|
| `settings/shop` | `{ name, palette }` | ทุกคน (ลูกค้าต้องเห็นชื่อร้าน) |
| `menu/{id}` | `{ name, price, cat, sort, emoji, img, soldout }` | ทุกคน |
| `tables/{token}` | `{ no, active }` | เปิดได้ทีละใบถ้ารู้ token |
| `orders/{id}` | `{ token, table, items[], total, status, createdAt, edited }` | admin เท่านั้น |
| `stats/{YYYY-MM-DD}` | `{ day, month, total, bills, items{} }` | admin เท่านั้น |

`items[]` = `[{ menuId, name, price, qty }]` — **ราคาถูก snapshot ไว้ตอนสั่ง** ขึ้นราคาทีหลังยอดย้อนหลังไม่ขยับ

`status` = `new` (รอเสิร์ฟ) · `done` (เสิร์ฟแล้ว) · `cancelled` (ยกเลิก ไม่นับยอด)

## ขั้นตอนขึ้นระบบจริง

### 1. เตรียมบัญชี
สร้าง **Gmail ใหม่ของร้าน** แล้วทำทุกอย่างบนบัญชีนั้น (ส่งมอบง่าย ไม่ต้องโอนทีหลัง)
ผูกเบอร์โทรของร้านไว้กู้รหัส

### 2. สร้าง Firebase project
Console → Add project → เปิด **Firestore Database** เลือก **production mode** (ห้าม test mode)

### 3. สร้าง Web app แล้วคัดลอก config
Project settings → Your apps → Web → คัดค่าไปใส่ `public/assets/config.js`
ใส่ project id ใน `.firebaserc` ด้วย

### 4. เปิด Authentication แล้วสร้างบัญชี
Authentication → Sign-in method → เปิดเฉพาะ **Email/Password**
Users → **Add user** สร้างทีละบัญชี → **คัดลอก uid ของทุกบัญชีเก็บไว้**

| บัญชี | ตัวอย่างอีเมล | ระดับ |
|---|---|---|
| เจ้าของ / ผู้จัดการ | `manager@ร้านเรา.com` | manager |
| พนักงานหน้าร้าน | `staff1@ร้านเรา.com` | staff |
| พนักงานคนที่ 2 | `staff2@ร้านเรา.com` | staff |

> ระบบนี้ไม่มีหน้าสมัครสมาชิก บัญชีสร้างจาก Console เท่านั้น
> ตั้งรหัสผ่านอย่างน้อย 8 ตัว ผสมตัวเลข และ **ห้ามใช้รหัสเดียวกันทุกบัญชี**

### 5. สร้าง doc `settings/roles` — ขั้นตอนที่ห้ามข้าม

Firestore Database → Start collection ชื่อ `settings` → Document ID = `roles` → ใส่ 2 field แบบ **array**

```
managers : ["UID_ของผู้จัดการ"]
staff    : ["UID_พนักงาน1", "UID_พนักงาน2"]
```

**ถ้าไม่มี doc นี้ จะไม่มีใครเข้าระบบได้เลย**

เปลี่ยนพนักงานทีหลัง = แก้ array ใน doc นี้จาก Console ไม่ต้อง deploy อะไรใหม่
คนที่ลาออกให้เอา uid ออกจาก array **แล้วลบ user ทิ้งใน Authentication ด้วย**

### 5.1 ใส่ uid เจ้าของใน rules เป็นกุญแจสำรอง
เปิด `firestore.rules` วางแทน `PASTE_UID_OWNER` ด้วย uid ของผู้จัดการ
กันกรณี doc `roles` หายหรือพิมพ์ผิดแล้วล็อกตัวเองออกจากระบบ

### 5.2 สิทธิ์ของแต่ละระดับ

| | ผู้จัดการ | พนักงานหน้าร้าน |
|---|---|---|
| เห็นออเดอร์วันนี้ / กดเสิร์ฟ / แก้บิล | ✅ | ✅ |
| ยอดขายวันนี้ | ✅ | ✅ |
| **ยอดขายรายเดือน / ย้อนหลัง** | ✅ | ❌ |
| **แก้เมนู ราคา อัปโหลดรูป** | ✅ | ❌ |
| **เพิ่ม/ลบโต๊ะ ปริ้น QR** | ✅ | ❌ |
| ตั้งชื่อร้าน / ธีมสี | ✅ | ❌ |
| ลบบิลถาวร | ✅ | ❌ |

เมนูด้านบนของระบบซ่อนหน้าที่ไม่มีสิทธิ์ให้อัตโนมัติ และ `firestore.rules` บล็อกซ้ำอีกชั้น
พนักงานพิมพ์ URL `/admin/menu` ตรง ๆ ก็เข้าไม่ได้

### 6. Deploy
```bash
npm install -g firebase-tools
firebase login
firebase deploy --only hosting,firestore:rules,firestore:indexes
```
ได้ลิงก์ `https://<project-id>.web.app`

### 7. ตั้งค่าเริ่มต้นในระบบ
1. เปิด `/admin` ล็อกอินด้วยบัญชีข้อ 4
2. แท็บ **จัดการเมนู** → ตั้งชื่อร้าน เลือกธีมสี → กด **ใส่เมนูตัวอย่าง** แล้วแก้ให้ตรงกับร้าน → ใส่รูป
3. แท็บ **โต๊ะ & QR** → ใส่เลขโต๊ะ กดเพิ่มทีละโต๊ะ → กด **ปริ้น QR ทั้งหมด**
4. ปริ้นแล้วเคลือบกันน้ำก่อนแปะ

### 8. เปิด App Check (ทำก่อนเปิดร้านจริง)
Console → App Check → reCAPTCHA v3 → ลงทะเบียนโดเมน → คัด site key ใส่ `RECAPTCHA_SITE_KEY` ใน `config.js` → กด **Enforce** กับ Cloud Firestore

ถ้าไม่เปิด ใครก็ยิงสร้างออเดอร์ปลอมได้จากนอกเว็บ

### 9. เชื่อม GitHub ให้ deploy อัตโนมัติ
1. push โปรเจกต์ขึ้น GitHub repo (private ได้)
2. GitHub → Settings → Secrets and variables → Actions → New repository secret
   - `FIREBASE_PROJECT_ID` = project id
   - `FIREBASE_SERVICE_ACCOUNT` = เนื้อไฟล์ JSON ทั้งไฟล์ จาก Firebase Console → Project settings → Service accounts → Generate new private key
3. push ขึ้น `main` → deploy เอง

## มาตรฐานรูปเมนู

อัปโหลดได้เฉพาะ **ผู้จัดการ** ระบบแปลงให้อัตโนมัติทุกไฟล์ ไม่ต้องเตรียมรูปมาก่อน

| ขั้นตอน | ค่า | แก้ได้ที่ |
|---|---|---|
| รับไฟล์ | รูปอะไรก็ได้ที่เบราว์เซอร์เปิดได้ (JPG PNG WEBP HEIC จากมือถือ) | — |
| ย่อด้านยาวสุด | **420 px** | `IMAGE_MAX_PX` |
| แปลงเป็น | **JPEG** | คงที่ |
| คุณภาพเริ่มต้น | **0.68** ลดทีละ 0.1 จนไฟล์ผ่านเพดาน (ต่ำสุด 0.3) | `IMAGE_QUALITY` |
| เพดานขนาด | **40 KB** ต่อรูป เกินแล้วปฏิเสธ | `IMAGE_MAX_BYTES` |
| เก็บที่ | field `img` ของ `menu/{UID}` เป็น data URI | — |

`firestore.rules` เช็คซ้ำฝั่ง server: ต้องขึ้นต้นด้วย `data:image/jpeg;base64,` และยาวไม่เกิน 60,000 ตัวอักษร
ต่อให้แก้โค้ดฝั่ง client ก็ยัดรูปใหญ่เข้า DB ไม่ได้

**ทำไมต้องคุมขนาด:** รูปถูกส่งไปให้ลูกค้าทุกคนที่เปิดเมนู เพดาน 40 KB คือสิ่งที่ทำให้ยอด egress
อยู่ที่ ~4 GB จากโควตาฟรี 10 GiB ต่อเดือน ถ้าปล่อยเป็น 100 KB จะทะลุโควตาที่ 13.5 GB

## ทดสอบว่าปิดช่องโหว่จริง

เปิดหน้าเมนูลูกค้าแบบไม่ล็อกอิน กด F12 แล้วลองทีละอัน — **ทุกอันต้องขึ้น `permission-denied`**

| ลอง | ต้องได้ |
|---|---|
| อ่าน `orders` ทั้งหมด | ปฏิเสธ |
| ไล่ดู `tables` ทั้งคอลเลกชัน | ปฏิเสธ |
| อ่าน `stats` | ปฏิเสธ |
| แก้ราคาใน `menu` | ปฏิเสธ |
| สร้างออเดอร์ด้วย token มั่ว | ปฏิเสธ |
| สมัครบัญชีเองแล้วอ่าน `orders` | สมัครผ่าน แต่อ่านไม่ผ่าน |
| อ่าน `tables/<token จริง>` | **ผ่าน** (อันเดียวที่ต้องผ่าน) |

ข้อรองสุดท้ายสำคัญที่สุด — ถ้าสมัครบัญชีเองแล้วอ่านออเดอร์ได้ แปลว่า rules ยังเช็คแค่ `request.auth != null` กลับไปแก้ให้เป็นรายชื่อ uid

## ดูทั้งระบบในไฟล์เดียว (ส่งต่อได้)

```bash
python tools/fetch-sample-photos.py    # ครั้งแรก
python tools/make-artifact.py          # ได้ dist/qr-order-demo.html (~0.7 MB)
```

ไฟล์ HTML ไฟล์เดียวที่มีทั้งระบบอยู่ข้างใน — เปิดจากที่ไหนก็ได้ ไม่ต้องรัน server ไม่ต้องต่อเน็ต
เหมาะกับส่งให้ลูกค้าดูก่อนตัดสินใจ

มีแถบสลับหน้า (มือถือลูกค้า / จอหลังร้าน / จัดการเมนู / ยอดขาย / โต๊ะ & QR),
เลือกโต๊ะ, สลับขนาดจอ (มือถือ / แท็บเล็ต / เต็มจอ) และปุ่มรีเซ็ตข้อมูล

**ทำงานยังไง:** โมดูลจริงจาก `public/assets/` ถูกแปลงเป็น `data:` URL ผูกด้วย import map
แต่ละหน้าเปิดใน `<iframe srcdoc>` เพื่อให้โมดูลรันใหม่ทุกครั้งที่เปลี่ยนหน้า
รูปอาหารย่อด้วยค่าเดียวกับระบบจริงแล้วฝังเป็น data URI
`public/` ไม่ถูกแก้ — การแก้ path/redirect ทั้งหมดเกิดตอน build เท่านั้น

## ทดสอบทั้งระบบก่อนขึ้น Firebase จริง

```bash
python tools/fetch-sample-photos.py     # ครั้งแรก: ดึงรูปอาหารทดสอบ 20 รูป
python tools/make-mock.py               # สร้าง mock/ จาก public/
cd mock && python -m http.server 8000
# เปิด http://localhost:8000/
```

รันระบบจริงทั้งระบบโดยไม่ต้องมี Firebase project, ไม่ต้องลง Java, ไม่ต้องลง firebase-tools

**ทำงานยังไง:** คัดลอก `public/` ทั้งโฟลเดอร์มาไว้ที่ `mock/` แล้วแทรก
[import map](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/script/type/importmap)
ให้ URL ของ Firebase SDK ชี้ไปที่ตัวจำลองที่เก็บข้อมูลใน `localStorage` แทน
**โค้ดใน `public/` ไม่ถูกแก้แม้แต่ไบต์เดียว** — หน้าที่รันคือไฟล์จริงทุกบรรทัด

seed ให้อัตโนมัติ: เมนู 20 รายการพร้อมรูป · โต๊ะ 8 โต๊ะพร้อม token · บัญชี 2 ระดับ

| บัญชี | อีเมล | รหัสผ่าน | เข้าถึงอะไรได้ |
|---|---|---|---|
| **ผู้จัดการ** | `manager@demo.local` | `123456` | ทุกหน้า — แก้เมนู ราคา รูป โต๊ะ QR ยอดรายเดือน |
| **พนักงานหน้าร้าน** | `staff@demo.local` | `123456` | เฉพาะออเดอร์ + ยอดขายวันนี้ |

หน้าล็อกอินในโหมดจำลองมีปุ่มให้กดกรอกบัญชีอัตโนมัติ ไม่ต้องพิมพ์เอง

**realtime ข้ามแท็บทำงานจริง** — เปิดหน้าลูกค้าแท็บหนึ่ง จอหลังร้านอีกแท็บ
กดสั่งแล้วออเดอร์เด้งขึ้นทันที (ใช้ `storage` event)

### หน้าลูกค้ายืดหยุ่นตามจอ

| ขนาดจอ | เลย์เอาต์ |
|---|---|
| มือถือแนวตั้ง (< 600px) | 1 คอลัมน์ รูป 82px |
| มือถือแนวนอน / tablet แนวตั้ง (600–1023px) | **2 คอลัมน์** จำกัดกว้าง 860px รูป 92px |
| tablet แนวนอนขึ้นไป (≥ 1024px) | **3 คอลัมน์** จำกัดกว้าง 1180px แถบตะกร้าเรียงแนวนอน |
| จอสูงน้อยกว่า 520px | ย่อ header ซ่อนข้อความชวน **แต่คงป้ายเลขโต๊ะไว้** |

- ใช้ `100dvh`/`100svh` แทน `100vh` — แถบ URL ของ Safari ยืดหดแล้วไม่กระตุก
- `env(safe-area-inset-*)` ครบทั้ง 4 ด้าน รองรับ notch ทั้งแนวตั้งและแนวนอน
- ปุ่ม +/− สูง 40px, chip 38px — ผ่านเกณฑ์ทัชขั้นต่ำของทั้ง iOS และ Android
- header กับแถบหมวดเป็นก้อน sticky เดียวกัน ไม่ใช้ `top` ตายตัวที่เลื่อนแล้วเหลื่อม

**ทดสอบไม่ได้:** `firestore.rules` — mock ไม่บังคับกฎ ต้องใช้ emulator ตัวจริง (ต้องลง JDK + firebase-tools)
ให้ไล่ตารางทดสอบเจาะระบบด้านบนหลัง deploy ขึ้น Firebase จริงแทน
